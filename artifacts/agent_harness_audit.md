# Agent Harness Audit (pre-integration)

**Baseline commit:** `a8fb18583424743e0ac68e9fedf082d07365fe49`

## Runtime entry point

- `src/agent.py::StochasticTutorAgent.answer` creates the public `AgentState`,
  restores compact experiment context from SQLite, invokes the compiled graph,
  and calls `src/graph/response.py::finalize`.
- `src/graph/workflow.py::build_graph` is the official LangGraph runtime.  It
  conditionally routes navigation, concept, simulation, practice/quiz,
  social/general conversation, and out-of-scope requests.
- `server.py` validates HTTP input and delegates question handling to the
  same `StochasticTutorAgent` instance; it does not own routing or tools.

## Current ownership map

| Concern | Current owner | Harness boundary |
| --- | --- | --- |
| Stateful sequencing and handoffs | `src/graph/workflow.py` | invoke only; no duplicate graph |
| Course evidence | `src/knowledge.py` | preserved as retrieved evidence |
| Evidence sufficiency | `StochasticTutorAgent._update_answerability` and bounded supplement edge | observe status; no replacement gate |
| Numerical truth | registered Python functions in `self.tools` and experiment registry | observe/verify result; no new executor |
| Learner assessment | `src/agents/handoffs.py::assess` | preserved; only assessed events update mastery |
| Next learning action | `src/agents/handoffs.py::recommend` / Curriculum agent | preserved |
| Persistence | `src/memory.py` SQLite | context snapshot reads compact fields only |
| Language synthesis | `src/llm.py` and Tutor response logic | existing provider/retry/circuit logic reused |
| Provenance and response checks | `src/llm.py::preserves_verified_facts`, visualization validators, response finalizer | centralized adapter/metadata only |

## Existing execution paths

1. **Concept:** classify → retrieve → evidence/supplement (bounded) → respond.
2. **Simulation:** classify → retrieve → evidence/supplement → plan → registered
   Python tool → diagnose → memory → respond.
3. **Practice/quiz:** classify → Assessment → Curriculum → respond.
4. **Navigation:** classify → Curriculum → navigation response.
5. **Social/general/out-of-scope:** classify → terminal response, bypassing
   retrieval, tools, and mastery updates where applicable.

## Existing safety and verification

- Provider retry, timeout, circuit breaker, UTF-8 request handling, and safe
  provider metadata already live in `src/llm.py`; the Harness must not duplicate
  or replace them.
- Simulation values are generated by Python tools and projected through the
  existing visualization contracts.  `preserves_verified_facts` protects
  verified result blocks and numeric/source anchors when a hosted rewrite is
  used.
- `src/graph/response.py` already exposes workflow, source, tool, answerability,
  timing, provider, and token metadata in the API observability contract.

## Harness gap and integration decision

The missing layer is a small, explicit boundary around the existing graph:
deterministic context compaction before execution, one execution entry point,
post-run verification/failure categorization, and normalized debug telemetry.
The integration will add `src/harness/` without adding Agents, tools, routing,
retrieval, grading, or a generic code/shell executor.  Student-facing answers
and existing API fields remain unchanged; Harness fields are debug metadata.
